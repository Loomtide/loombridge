# Loombridge

**Agent layer to build and verify games in Unity.**

Loombridge is an agentic toolset by [Loomtide](https://loomtide.ai/) to build games end to end.

Good games are not generated by one prompt, they are iterated to achieve an experience. Loombridge
has a set of tools to plan, build, verify and test games.

**There is a demo video and the full documentation on
[GitHub](https://github.com/Loomtide/loombridge).**

## Install

```bash
npm install -g loombridge
```

Then wire your Unity project, in one command, from inside it:

```bash
cd /path/to/UnityProject
loombridge setup           # bridge + MCP registration + (optional) agent surface, then doctor
```

To update later, run this from your Unity project:

```bash
loombridge update          # add --check to see what would change without installing
```

Restart your agent session and it should pick up the new commands and MCP.

```
> claude
> /loombridge:plan  I want to build a 3D first person sniper shooter. Where player
                  is static in a location like top of building and we only see
                  first person sniper gun. Player needs to aim at enemies in far
                  locations and buildings.  [reference screenshot attached]
```

Every command tells you what to do next. For the prompt above, here is the generated
[SniperShooter](https://github.com/Loomtide/SniperShooter).

## Build flow

Three commands to build the game to your design. These work with Claude, Codex or Cursor, and
extend easily to any agent.

- `loombridge:plan` generates a hero shot from your initial idea, and the slices that build it.
- `loombridge:build` executes the slices generated by plan.
- `loombridge:status` tells you where you are in development.

## Verify flow

Record the gameplay once and replay it indefinitely. No AI agent is involved, so replays cost
nothing. Record while you build the feature; the recording is saved in `.loombridge/`. Later, in CI
or on another machine, run `loombridge verify` and it tells you whether the game still plays the
same.

- `cd /path/to/UnityProject`
- Keep the Unity project open.
- `loombridge record` starts Unity in play mode. Play the flow you want to record.
- Return to the CLI and press enter. Recording is done.
- `loombridge verify` re-drives the recording in Unity and captures the frames.
- `loombridge approve` marks the recording as the baseline for future checks.
- From then on, `loombridge verify` runs the game and generates a report.

This is work in progress: the goal is to cover more use cases and automate more classes of issue.

## Game tuning and feel verification

Early stage, but Loombridge can snapshot your configs and then replay the game to check it still
plays like the baseline you recorded. It is more than diffing the snapshot: it plays the game and
checks frame deltas, so it can tell you whether the jump height still matches what you recorded.

## Security posture

Loombridge is a local, single-developer editor tool. The agent talks to the MCP server over stdio;
the MCP server talks to a bridge inside your Unity Editor over loopback only. No raw-eval op, no
telemetry, no cloud requirement. Exposing the bridge to a network is an unsupported configuration,
not a feature.

Report vulnerabilities privately per
[SECURITY.md](https://github.com/Loomtide/loombridge/blob/main/SECURITY.md); the full model is in
[Docs/ThreatModel.md](https://github.com/Loomtide/loombridge/blob/main/Docs/ThreatModel.md).

## Non-goals (permanent, not missing features)

- **No arbitrary code-execution op.** The typed op registry is a security boundary; gaps are closed
  with typed ops, never an eval escape hatch.
- **No telemetry.** No analytics, usage beacons, or phone-home. This will not change.
- **No cloud requirement.** Core CLI and bridge run fully local.
- **Not a game factory.** Loombridge carries no opinion about what a good game is; it is the
  machinery for stating yours once and enforcing it forever.

## Help and bugs

Questions, ideas, or want to show what you built? Come to
[Discord](https://discord.gg/dTBpd8Embh).

Something broken or missing?
[Open an issue](https://github.com/Loomtide/loombridge/issues). The fastest reports include the
command you ran and the report it wrote under `.loombridge/run/reports/`, since that names what was
checked and what was not.

Security vulnerabilities go through
[SECURITY.md](https://github.com/Loomtide/loombridge/blob/main/SECURITY.md) privately, not a public
issue.
